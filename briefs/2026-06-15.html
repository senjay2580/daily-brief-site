AI 编程实战技巧

  • "结构胜过模型"：Loop Engineering 与目标导向的 Agent 设计：本轮编程方法论的核心论点——能以"有用状态"完成任务，十有八九不是因为模型更好，而是因为围绕目标的结构更好。典型失败模式高度一致：上下文被稀释、一个错误演变成全局重启、之前学到的东西消失、验证来得太晚。配套出现 32 页《Loop Engineering 橙皮书》（作者称由自己的 skill 自动整理多源信源写成），并澄清 Loop Engineering 是高阶 Agent 设计哲学（Plan-Act-观察循环、状态持久化、中断恢复），Codex Goal 只是其实现工具之一，不必因新名词 FOMO。

  • Codex 实战工作流：声音 Hook、多账号负载均衡、远程控制：一批 Codex 重度用户的工作流技巧：用 Hook 给 Codex 换上更具穿透力的声音反馈，让任务开始/请求权限/执行完成都能第一时间被分心的人类感知，解决"Codex 干活时太安静"的问题；给桌面端 Codex 做多账号负载均衡，还能用 iOS 远程控制。还有人把 vibe business 工作流总结为 feishu + Claude Code + Codex 的组合。

  • 一人公司/独立开发的 AI 默认技术栈：一份被转发的"一人公司"默认栈：Claude（写代码全栈，$20/月）+ Supabase（后端，免费）+ Vercel（部署，免费）+ Namecheap（域名）+ Stripe（支付，2.9% 抽成）+ GitHub + Resend（邮件）+ Clerk（认证）。配套观点：别再每开新项目就手搓脚手架，Better-Fullstack 支持 TS/Rust/Python/Go 四大生态、270+ 技术栈组合（前端/后端/数据库/Auth/支付/AI/DevOps 一次选完）。

  • 给 Claude/Codex/Cursor 装"无限内存"：开源记忆层成新刚需：上下文记忆成为本轮编程 Agent 的焦点工具。Memanto（GitHub 5000+ 星、免费开源）号称给 Claude Code / Codex / Cursor / LangGraph / CrewAI 赋予"无限内存"：保存工作会话上下文、用 AI 压缩组织、90ms 内检索，无需向量数据库与复杂配置。另一个 Obelisk v0.1.0 则把散落的 Claude Code session 变成可检索层，让 agent 快速追溯历史、并查看其为减少重复检索而存储的 markdown。

  • 工具文档是写给 LLM 看的：Agent 工具链设计要点：一条高质量的工程经验：工具文档是写给 LLM 的，不是给人看的，大多数 Agent 工具链翻车的根源就是把这两者搞混。LLM 通过 docstring 决定选不选你、通过参数名决定传什么值、通过返回值决定下一步——把这三件事设计好，工具自然被正确使用。

  • AI 图像 prompt 工程化：从"自己想一段话"到结构化系统：出图不稳定的根因是 prompt 不结构、不参考。社区推的解法是把 prompt 做成工程化系统：songguoxs/gpt4o-image-prompts 收录 1145+ 中文 AI 图像提示词，覆盖 Nano Banana Pro / GPT-5 / Grok / 豆包；另一个库做到 Agentic 级别——32 场景分类、19 节 Prompt 工艺手册、CLI 一行跑、可作为 Agent Skill 装进 Claude Code，"出图不靠运气靠结构"。配套观点：以后会写分镜的人比会喊"电影感"的人贵。

  • 信息处理工作流：RSS 减噪、App 评价挖掘、DeepSeek 桌面台：一批把"信息洪流"变成可用工作流的工具：FeedFuse（371 星，TypeScript/AGPL-3.0）把"订阅→过滤→阅读→理解→汇总"串成一条流，用关键词+AI 减噪治 RSS 焦虑；有人做工具输入任意 App 名自动抓 AppStore 评价、用 DeepSeek 挖出用户在夸什么骂什么、哪些是产品机会（计划开源）；DeepSeek 还出了桌面工作台 GUI，含 Code/Write/连接手机/技能与 MCP 四大模式，运行时为自带的 Kun（TypeScript 包，起本地 HTTP/SSE 服务）。

  • AI 代码注释与"无限上下文"宣传祛魅：两条务实的踩坑/技巧：一是针对"AI 爱在代码里乱写注释"，有人专门写了一份提示词，让 AI 产出比自己写的还优质的代码注释；二是对小米 MiMo Code"无限上下文"的宣传，有人把代码下下来扔进 Claude Code / Codex 实测，结论是"没那么玄乎，说到底也是上下文压缩"。

  • AI 生成原生 macOS 应用与论文配图：代码/设计生成进一步下沉到具体产物：Ironsmith 靠 AI 描述需求就能一键生成 SwiftUI 原生小应用，被调侃"原生 macOS 小工具不用开发了"。学术侧，有工具输入 PDF/摘要/方法说明即可自动生成 method overview、架构图、流程图、agent 工作流图，解决论文框架图手画的折磨。

  • Codex × 硬件 / 数据分析：软硬结合与官方插件：Codex 的能力边界在扩张：有人把 ESP32 直接"丢给 Codex"就生成了一个监控看板，演示软硬结合的玩法。OpenAI 官方还出了 Codex 数据分析插件教程——让 Codex 当智能体数据分析师，自动跨系统收集背景、生成报告、图表实时改动、数据源全透明、可导出到 Google 工具，工作流端到端可见。

  • 把数据源"打通"成 Agent 能用的技能：数据获取正被封装成 Agent 直接可调的 skill：有项目把A 股 + 美港股免费数据源彻底整合成 AI 能直接用的数据仓库，封装成 Skill 后让 Claude/GPT 等 agent 告别接口对接、反爬与数据费。更广义地，有人称"AI Agent 5 年第一次看得见整个互联网"——16+ 平台一站搞定、0 API 费、一句话发给 Agent 三分钟装完（对比过去 16 个 API key + 16 套反爬 + Cookie 登录噩梦）。

  • 不用生图模型也能出图：LLM + 几何算法渲染 SVG：一个反直觉的技巧：某个看似 AI 画图的效果其实根本不用生图模型——流程是 pi + DeepSeek：先让 LLM 把大白话变成结构化 JSON，再用 Node.js 渲染器以纯几何算法算出 SVG，最后塞进自包含 HTML。适合可结构化、可计算的图形场景，确定性远高于扩散模型。

港口引航

引航员引领船舶不解除船长责任：强制引航是一套『建议而不接管』的双向风控

强制引航的本质是双向风险管理——既替不熟悉本地水域的外籍船保护港口、航道与环境，也用法律把引航员与船舶的商业利益隔离开（『州引航员判断不安全，船就不能动』）。中国《海上交通安全法》（2021-09-01 施行）第30条规定外籍船、核动力船/载放射性物质船/超大型油轮（VLCC）、散装液化气与危化品船、以及尺度接近航道极限的船舶必须申请引航；第102条对不申请强制引航者可处船舶所有人/经营人 5 万至 50 万元罚款。

引航最危险的常规动作是登轮——从行进中的引航艇爬上引航梯。SOLAS V/23 用爬高分档管控：低于 1.5m 不需梯，1.5–9m 必须用引航梯，超过 9m 必须用『组合舷梯』（accommodation ladder + 引航梯），因为从超过 9m（约 30 英尺）落水被认为可能致命。IMPA 数据显示 2001–2021 二十年间共记录 32 名引航员死亡（约 1.8 人/年），其中约 75% 的事故发生在引航梯上。

内行最强调的认知差是 conduct（操纵）≠ command（指挥）：即便强制引航法规授权引航员操纵航行，船长始终保留指挥权、否决权与介入义务，法律责任也从不因『引航员在操船』而转移给引航员；中国法第31条同样写明『引航员引领船舶时，不解除船长指挥和管理船舶的责任』。每次任务都从面对面的 Master-Pilot Exchange 开始，交换操纵特性、停船距离、航路计划与应急方案，交换不满意引航员可拒绝开航。

行业思维：把外籍船长的盈利冲动与本地航行安全用法律责任隔离开，才是强制引航真正的控制点——引航员只建议、不接管，船长的责任一刻也不卸。

茶叶审评

0 分代表『和标准样一个水平』：茶叶审评赌的不是好味觉，而是对样的可复现

茶叶审评按 GB/T 23776《茶叶感官审评方法》打分，五项因子（外形、汤色、香气、滋味、叶底）各按 0–100 分乘以『评分系数』再求和：Y = A·a + B·b + … + E·e。关键在于系数随茶类变化——几乎所有茶滋味权重最高（30%），乌龙茶把汤色压到 5%、滋味提到 35%（重香气与耐泡），花茶把香气提到 35%，粉茶叶底直接归 0。

判定有两套并行机制：『七档制』对照标准样在 +3 到 −3 间打分，0 分字面意思就是『与标准样相当』，任一因子 −3 即判不合格；『加权评分法』用百分制×系数排优次，并列时按 滋味→外形→香气→汤色→叶底 固定顺序破。级别判定是把未知样与一组实物标准样比对，最终级别=（外形级别+内质级别）÷2，标准样按 GB/T 18795 有 3 年有效期、到期实物换发，刻意维持参照基线受控。

整套审评室也是为剥离环境变量而设计：GB/T 18797 规定审评室坐南朝北用稳定北向自然光（避免阳光『雀斑光点』干扰汤色判断），墙体乳白、地面灰、无异味，评茶员不得吃蒜辣、不得用香水，干评台约 1000 lx、湿评台不低于 750 lx、噪声不超过 50 dB。内行与外行的差距不在『舌头灵』，而在对着固定实物标准样长期稳定复现同一判断。

行业思维：审评的壁垒不是绝对味觉，而是用实物标准样、统一冲泡（1:50、100℃、5 分钟）与北向光审评室把一切变量约束掉，让分数能跨评茶员、跨实验室复现。

纺织印染

一次成功率（RFT）才是染厂命门：每次返染≈3200L 水，70%→95% 总成本降约 44%

染厂真正的核心 KPI 是 Right-First-Time（一次成功率）——不返修、不修色就达标的批次占比，因为每一次修色都要再烧化学品、水、能源与机时。多数染厂 RFT 低于 75%，把返工当成必然；而把 RFT 从 70% 提到 95% 可使总生产成本下降约 44%，省下被返工占用的约 30% 机台产能，每个返染批次约多耗 3200L 水与等量废水，还会因额外热/机械循环损伤布面。

颜色是否过关由两道并行闸门决定：仪器 ΔE（分光光度计）+ 灯箱里人眼『商业可接受匹配』。商业容差通常 ΔE≈1.0–1.5；但 CIELAB(CIE76) 并非感知均匀——同样 ΔE 在某些色区明显、在另一些几乎看不见，所以纺织业改用 CMC l:c（默认 2:1，加倍放宽明度容差）、CIE94/CIEDE2000，并常对 ΔL/ΔC/ΔH 分别设容差，而非单一 ΔE。色牢度按灰卡 1–5 级评（ISO 105-A02 变色 / A03 沾色），3–4 级通常是买家验收下限，且美标 AATCC 与欧标 ISO 同布不同分。

内行真正对抗的是同色异谱（metamerism）：两块布在 D65 下完全一样，换到零售店的 TL84/CWF 或白炽灯 A 光源下却『刺眼地不一样』，因为它们的反射光谱曲线不同。所以匹配必须在标准灯箱里用多光源（D65 主参考 + TL84 + CWF + A + UV）同时评判，至少两到三种光源都过才算过——配方师选的是光谱曲线彼此跟随的染料组合，而不只是凑一个 ΔE 数字。反应染料还要分清『上染≠固色』：盐促上染、碱（pH≈10.5–11）促成共价固色，未固色的水解染料必须高温皂洗洗掉否则毁掉水洗/摩擦牢度。

行业思维：染色的成本与壁垒都压在『一次成功』上——把实物标准样在多光源下无同色异谱地、批批可复现地一次命中，才是手艺；『把颜色染上去』反而是最不值钱的一步。

兽医诊疗

猫狗麻醉死亡率是人的 10–20 倍：病人不会说话，剂量也不能照人/狗换算

兽医麻醉的基准研究是 CEPSAF（Brodbelt 2008，近 9.8 万只狗、7.9 万只猫）：术后 48h 内麻醉相关死亡，狗总体 0.17%（约 1/601）、猫 0.24%（约 1/419）；健康（ASA 1–2）狗仅 0.05%、猫 0.11%，而重症（ASA 3–5）升到约 1.33%/1.40%——病情每升一级风险约放大 25 倍。对照人类麻醉相关死亡约 0.01–0.02%，猫狗高出约 10–20 倍，差距主要来自监护标准而非物种生理；且多数死亡发生在术后（狗 47%、猫 61%），术后前 3 小时最关键。

第二个硬约束是物种特异性药物毒性——剂量必须按物种逐一重新推导，不能照人或狗换算。猫缺少关键的葡糖醛酸转移酶（UGT1A6/1A9），清除慢、毒性代谢物蓄积：对乙酰氨基酚对猫无安全剂量，低至 10 mg/kg 就可中毒；扑灭司林（permethrin）等拟除虫菊酯对猫是神经毒；而木糖醇只毒狗（>100 mg/kg 低血糖、>500 mg/kg 肝衰），猫不敏感。把狗的驱虫药用在猫身上是经典的致死场景。

最根本的认知差是『病人不会说话』+ 猎物物种隐藏病痛：诊断只能靠主人病史、体格检查与影像/化验三条腿，而兔、豚鼠、啮齿乃至猫会本能掩盖疼痛与疾病，等表现出来往往已经很重。所以兽医用行为化疼痛量表、分级分诊，并把主人当不可靠的『代述者』（可能隐瞒人药/误食），靠瘀斑、黑便等体征反向追问。安乐死与生活质量（Villalobos HHHHHMM 量表，>35/70 为可接受）则是人医里几乎没有的常规临床决策。

行业思维：兽医的风险控制点在于：病人不会说话、猎物天生藏病、剂量不能跨物种照搬——所以每一个 mg/kg 都要按物种重算，分诊与术后监护标准才是把麻醉死亡率压下来的关键。

期权做市

做市商不赌方向：靠 delta 对冲赚价差，真正的边是 IV>RV 的方差风险溢价

期权做市商的本职是『买价买、卖价卖』赚买卖价差，而不是判断涨跌。一旦成交就背上方向风险（delta），他立即用标的买卖把『期权+标的』的净 delta 对冲到约 0（如 +0.50 delta 的 ATM 看涨，靠卖空 0.5 单位标的中和）。这与投机/自营的本质区别在于：做市商对当下价格『理论上无所谓』，而投机者的盈亏恰恰依赖方向判断。但对冲不是一次性的——标的一动 delta 就漂移，必须随实现波动持续再对冲。

整张账本用希腊字母当控制面板：先用 delta 对冲快速清掉方向风险，再交易掉期权特有的 Gamma（凸性）、Vega（对隐含波动率敏感）、Theta（时间衰减），并通过偏移报价避免某类希腊风险越积越多。长 Gamma 用 gamma scalping 把实现波动变现：标的涨→delta 转正→高卖，标的跌→delta 转负→低买，机械地『低买高卖』。但长 Gamma 要付 Theta『租金』，只有实现波动 > 隐含波动才赚；其 P&L≈½·Γ·S²·(σ²实现−σ²隐含)·Δt，且路径依赖。

真正的边不是预测价格，而是比对手更准地估波动率——做市商围绕整张波动率曲面报价。结构性 payoff 是『方差风险溢价』（VRP）：隐含波动率长期高于随后实现的波动率（卖波动像卖保险），AEA 论文发现风险中性方差平均比实现方差高约 2.13%、『每年都稳健为负』。但这是风险补偿不是白捡——2008 年 10 月一个简单卖波动策略曾亏超 48%。做市商最大的敌人是逆向选择（和信息更优的对手交易），防御手段是在财报前/异动时加宽价差，并因隔夜跳空风险在收盘前把仓位拉平。

行业思维：做市的决策核心是把方向风险对冲为零、只赚价差与 IV>RV 的方差风险溢价，再用加宽价差防逆向选择、收盘拉平防跳空——它管理的是一整张希腊字母账本，而不是单笔赌方向。
